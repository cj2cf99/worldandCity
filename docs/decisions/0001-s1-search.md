# 0001 S1：`search_norm` + `LIKE` 基线与 FTS5 trigram

- 日期：2026-11-10 ／ 对应：设计 §4.2「搜索」、§7.6、§13 S1；复审 M2
- 复现：`node spikes/s1-search.mjs`（虚构词条，内存库，不被测试或构建引用）
- **环境**：本机 `node:sqlite`（SQLite 3.54.0）。**D1 未验证**，见 [`0003`](0003-wrangler-blocked-steps.md)。

## 问题

基线方案（应用层规范化写入 `search_norm` 列，再用 `LIKE '%词%'`）能否检索中文 2 字词与短句？FTS5 trigram 是否值得作为升级选项？

## 做法

用 9 条虚构词条（中文、带括号、英文、带重音字母）；规范化 = NFKC + 小写 + 去空白与标点（`\p{P}`）。分别查询 LIKE 与 FTS5 trigram。

## 结果

| 查询 | LIKE 基线 | FTS5 trigram（短语匹配） |
|---|---|---|
| 单字 `安` | 命中 3 条 | 未测（trigram 至少需 3 个字符） |
| 2 字 `西安` | 命中 3 条 | **0 条（无法检索）** |
| 3 字 `西安钟` | — | 命中 1 条 |
| 4 字 `西安钟楼` | 命中 1 条 | 命中 1 条 |
| `PARIS`／`Café` | 大小写、重音字母经规范化后命中 | 未测 |
| 带全角括号 `（西安）` | 规范化去掉括号，命中 | 未测 |

- FTS5 trigram 在本机可建表（`available: true`）。

## 决定

1. **基线用 `search_norm` + `LIKE`，维持设计 §4.2 不变。** 中文检索以 2 字词为主，trigram 对 2 字词零结果，不能替代。
2. **FTS5 trigram 只作为"≥3 字查询"的将来加速手段，不是整体替代。** 升级阈值（约 2 万可检索行）不变；真要升级，须保留 2 字词走 `LIKE` 的分支。该点已同步到设计 §7.6。
3. 规范化会去除 `%`、`_`（均属 `\p{P}`），因此用户输入不会变成 `LIKE` 通配符；**服务层仍须做这一步规范化后再绑定参数**，不得直接把原始输入拼进模式。

## 未验证

- **D1 的 `LIKE` 模式 ≤ 50 字节**：D1 的限制，本地 SQLite 无此限制，本地无法复现。待 D1 环境验证；设计已规定超长查询词截断到约 16 个汉字。
- D1 是否提供 FTS5 trigram：未验证。
- `LIKE` 全表扫描的 `rows_read`：数据量小时可接受，真实数据量下未测。
