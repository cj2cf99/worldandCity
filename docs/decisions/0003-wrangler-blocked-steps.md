## 2. 对 M0 退出条件的影响（需要用户知悉）

里程碑 M0 写明："若 S2 失败……若 S11 失败……两种情形都应在进入 M1 前确定。"现在 S2、S11 **既没有失败也没有通过**。因此：

- **M0 不能宣布"完全通过"**，只能宣布"M0 本机可做的部分完成"，B1–B4 挂起。
- 继续开发的风险：若日后在别的环境验证发现 S2 或 S11 失败，需要回头改**尚未写出的代码**（触发器在 M5、迁移共存影响 M1 的部署配置），**目前已写代码不受影响**。
- 因此在 B1–B3 补做之前，开发限于**不依赖 D1 行为的部分**；涉及触发器的功能（M5 的 3 对象上限、5 条置顶）先不动工。

## 3. 补做办法（任选其一，由用户决定）

1. **GitHub Actions**：在 CI 里安装 wrangler 跑 B1–B3、B6（CI 已存在，可新增 job）。不在本机安装，也可得到 D1 本地模拟的结果。限制：B5 需要 Cloudflare 凭据，不能放在公开仓库 CI，只能手工执行。
2. **另一台电脑**手工执行并把结论写回 `docs/decisions/`。
3. **用户确认接受风险**，把 S2／S11 的备选方案（单条 `INSERT … SELECT … WHERE count<N`、手动迁移执行器）直接定为主方案，不再等验证。这会改变设计 §4.3／§4.5，须先同步修订设计文档。

## 4. 不依赖 wrangler、可继续的工作

- 业务代码里的**纯逻辑**与 SQLite 层：节点查询服务、`children` 三态、`ancestors`、`path` 工具函数等（M3）。
- 守卫补强、种子、测试。
- 前端壳与视觉原型（M2）：独立于 D1。
- M1 中的 Worker 路由、鉴权**逻辑**可写成与运行时无关的纯函数并用普通 Node 单测；真正挂到 Workers 运行时的集成测试标 B6。
