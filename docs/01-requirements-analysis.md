## 2. 新增确认的约束（2026-11-10）

这些约束优先于 PRD §16.1 中"非锁定"的技术方向。

| 编号 | 约束 | 分析与含义 |
|---|---|---|
| **C1** | 公开 GitHub 仓库，仅通用数据，禁止个人／私密数据 | 已写入 PRD §0-12。设计上要求**公开数据与私有数据物理分离**：公开数据走仓库；私有数据只存在于线上存储 |
| **C2** | 线上数据库采用 SQLite | Cloudflare 上的 SQLite 即 **D1**（SQLite 语义的托管数据库）。同一套 SQL 方言在本地 `node:sqlite` 与线上 D1 之间通用 |
| **C3** | 本地开发用 SQLite 库 | 用 Node 内置 `node:sqlite` **新建空库** `data/local/worldandcity-dev.sqlite`，允许入库；不依赖、不引用、不复制其他项目的代码或数据（2026-11-10 确认） |
| **C4** | 线上"恒定设置信息"用 **Cloudflare KV** | 只放低频修改、可容忍最终一致的配置。强一致或事务数据一律不进 KV |
| **C5** | 线上文件读写用 **Cloudflare R2** | 附件、较大几何、备份导出包等对象数据 |
| **C6** | **真实数据不要持续存放在本地** | 本地不保留真实数据的持久副本。例外（2026-11-10 确认）：仓库内的空开发库 `data/local/worldandcity-dev.sqlite` 允许入库，只放通用／示例数据。见 §2.2 |
| **C7** | 当前阶段不写代码 | 设计文档与评审为主 |

### 2.1 对 C3 的解读

- 本地与线上共用 SQLite 方言：本地用 Node 内置 `node:sqlite`，线上用 D1，因此无需额外数据库软件。
- 开发库是本项目**自行新建**的空库，不基于任何其他项目的文件。
- 本项目的迁移执行器、数据访问封装均**在本项目内自行实现**，不引用其他项目的路径或代码。

### 2.2 对 C6 的解读（"不持续存放在本地"）

| 数据类型 | 本地策略 |
|---|---|
| 开发用 SQLite | 固定文件 `data/local/worldandcity-dev.sqlite`，**已确认入库**，只含迁移结构与公开／示例数据；测试在内存库上运行 |
| 线上真实数据 | 只存在于 D1／KV／R2。**不从线上拉取任何数据到本地**（PRD §0-13）；复现问题用手工构造的虚构夹具 |
| 备份／导出包 | 生成后存入 R2（私有桶）；用户下载仅作临时传输，不建议在本机长期保留 |
| 构建产物、日志、缓存 | 不含个人数据；`.gitignore` 兜底（已配置） |
| wrangler 本地模拟状态 | 默认会写入本地状态目录；设计要求将其**指向临时目录或每次清理**（落地时核实具体参数） |

## 3. 数据分级（决定"什么能进仓库"）

| 级别 | 示例 | 可进公开仓库 | 线上落点 | 本地 |
|---|---|:---:|---|---|
| **L0 公开代码与文档** | 源码、迁移脚本、设计文档 | ✅ | 随部署发布 | 仓库工作区 |
| **L1 公开通用数据** | 公开来源且可再分发的国家／行政区层级与名称、公开地理轮廓（如 Natural Earth）、示例／演示 item、分类模板、详情文案模板 | ✅（须附来源与许可清单） | 部署时随静态资源或种子导入 | 仓库工作区 |
| **L2 私有配置** | 密钥、令牌、Access AUD、账号 ID、资源 ID | ❌ | Worker secret／变量；仅在 Cloudflare 控制台或密钥管理中保存 | 不落盘（或仅 `.dev.vars`，且被忽略） |
| **L3 私有业务数据** | 真实人物、地点、住址、历史记录、关系、真实坐标、置顶新闻、用户节点树选择 | ❌ | **D1** | 不保留 |
| **L4 私有文件** | 头像、照片、真实备份包、含个人信息的导出 | ❌ | **R2**（私有桶） | 不保留 |
| **L5 第三方受限数据** | 无再分发许可的地图数据（如 GADM）、新闻全文 | ❌ | 视许可决定，默认不存 | 不保留 |

**关键推论**

1. 公开示例数据和真实数据必须**结构相同、来源分离**：示例在仓库 `seed/`（L1），真实数据只在线上库（L3）。
2. 因为仓库公开，**地理节点树的"选择"本身也可能暴露个人信息**（例如"我只展开了某个小城市到街区"会暗示住址）。因此：仓库只放**通用节点库**；用户真实展开了哪些节点、哪些节点下有私有内容，属于 L3，只在线上库。
3. 这条要求改变了一个直觉：**不能把"我的节点树"当作种子提交**。种子只包含一个通用最小集（世界、大洲，及两条深度不同的通用示例路径：中国→陕西省→西安市→未央区；法国）。

## 4. 参与者与使用场景

- **唯一用户**：仓库所有者本人（PRD §0-9：单用户）。
- **访问者**：无。线上入口全部置于身份验证之后。
- **开发者／AI Agent**：只能访问公开仓库与 L1 数据；不接触 L3／L4。

典型场景：

1. 打开站点 → 通过身份验证 → 看到地球仪 → 展开地图 → 导航到节点 → 查看该节点下的人物、历史、新闻、趣闻。
2. 新增一条带模糊位置的历史记录（"小仓北区某面馆"），挂靠到已有最近节点，保留原文。
3. 把一条涉及多国的新闻绑定多个区域，只占一个新闻名额。
4. 导出自己的数据备份，或从备份恢复。
5. 开发者在临时本地库上重现问题，不接触真实数据。

| ID | 需求 | 来源 |
|---|---|---|

| NFR-3 | **全站鉴权**：所有 API 与页面均在身份验证之后；Worker 内再次校验令牌，不只依赖边缘 | PRD §0-9 |

## 7. 存储映射决策（需求视角）

| 数据 | 落点 | 理由 |
|---|---|---|
| 节点、item、位置、关系、分类、置顶、附件元数据 | **D1** | 需要事务、约束、索引、关系查询 |
| 全局展示参数、详情模板、节点 `kind` 值域、功能开关、外部适配器端点（非密钥） | **KV** | 低频改动、读多写少、容忍最终一致。分类定义（一级四类、二级）被外键引用，放 **D1** |
| 头像／图片、备份包（较大的私有几何后置） | **R2** | 对象存储；大对象；私有 |
| 公共底图（Natural Earth 等）、模型、贴图 | **静态资源（部署产物）** | L1 公开、随发布版本固定，走边缘缓存 |
| 密钥、令牌、AUD | **Worker secret／变量** | 不入仓库、不入 KV |

**禁止**：把需要强一致或需要唯一／数量约束的数据放入 KV（如新闻置顶、3 对象限制、关系去重）。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 误把真实数据或数据库文件提交到公开仓库 | 隐私泄露，且 Git 历史难以彻底清除 | `.gitignore`＋提交前扫描＋CI 检查＋种子目录白名单；密钥泄露按"立即轮换"处理 |
| 从其他项目拷入数据文件 | 引入与本项目无关的私密数据，违反 C1 | 开发库一律由本项目新建；提交守卫校验库内只含 `wc_` 表，且节点 `origin` 为 `seed／demo`、item `origin` 为 `demo`（设计 §3.2） |
| 节点树选择暴露个人信息 | 间接泄露居住地／关注点 | 仓库只放通用节点库；真实节点树仅在 D1 |
| KV 最终一致导致读到旧配置 | 配置改动短时不生效 | 只放低频配置；关键一致性数据放 D1；文档注明传播延迟 |
| D1 单库单线程，写入过多请求时可能排队 | 延迟抖动 | 单用户场景压力低；仍用 `batch` 合并写入；列表走索引 |
| 中文检索：`LIKE` 模式 ≤ 50 字节（约 16 个汉字）；FTS 对中文分词受限 | 搜索体验受限 | 基线用 `search_norm` 规范化列＋`LIKE`（单用户数据量小）；数据量超过约 2 万可检索行再升级 FTS5 trigram；S1 验证 |
| 地图数据许可（GADM 禁止再分发；OSM 需归属） | 公开仓库中二次分发违规 | 首选 Natural Earth（公有领域）；其余数据仅在线上使用并核验许可，不入仓库 |
| 180° 经线跨越的几何查询出错 | 太平洋事件漏查 | bbox 存储规则中显式处理跨经线（拆分或标志位），列入验收 |
| wrangler 本地模拟默认写本地目录 | 违反 C6 | 指向临时目录或会话后清理；纳入开发规范（S4） |
| 新闻／RSS 全文转载权利不明 | 版权风险 | 只存标题＋短摘要＋来源＋链接（PRD §22.3） |
