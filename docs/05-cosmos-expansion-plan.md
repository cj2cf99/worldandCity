## 3. 采纳与简化决定（对总纲的“不照搬”清单）

1. **数据契约不上 TypeScript／关系表**：不新增 `AstroObject` 字段与 `related` 表。每个节点沿用现有 `detail`（简介／离我们／有多大／小知识），新增一条 **“画面说明”**，写明数据等级（实测／重建／模型／示意）与来源；这已被信息卡直接展示。
2. **虚拟分类节点暂不建**：总纲自身要求这类节点“不生成物理球体”，没有子对象时是空壳。待对应 P1 对象获批再建，避免空目录。
3. **不做 V1／V2 两遍重写**：项目已把科学形态与艺术参数放在同一套代码里，并有统一的“科学／观赏”模式开关；每批在 dev-log 里写“科学数据说明在先、艺术参数独立”，不拆两遍。
4. **不做逐对象“绘制卡”文件、V1/V2 对比截图归档、手机竖屏双视口矩阵**：改为每批 dev-log 记录验证项与限制；预览环境不支持的项目写“未验证”。
5. **不接 JPL Horizons／Gaia 在线数据，不做双精度相机相对坐标**：本机离线，且单人浏览场景不需要；沿用二体开普勒近似并在页面注明。若日后能联网，再用 Horizons 对照三颗彗星与卫星。
6. **新节点优先复用已有场景**：本星系群场景里已有 M31／M33／LMC／SMC 的程序化模型；新增节点只做“落在父场景并放大到对应缩放目标”，不另写渲染器。
7. **标签密度与时间演示不单列规则**：总纲“每画面 3–7 个标签”由现有标签档位（隐藏／简洁／全部）满足；恒星自行的时间演示、坐标旋转与 Horizons 对照类自动测试不做（本项目的自动测试只覆盖种子与服务层，场景由浏览器实测）。
8. **参考层统一由「参考线」总开关管理**（用户 2026-11 决定），拉尼亚凯亚引力流线例外；总纲“所有参考层可单独隐藏”的要求以此满足，不再逐项拆分。

## 4. 与既有决定冲突的处置

- **奥尔特云与太阳系的层级**：总纲 §2 写“保留原导航：…本地泡→恒星邻域→奥尔特云→太阳系”，但其原则 1 又说“奥尔特云是太阳系外围组成部分，并非太阳系父天体”。用户此前已明确要求改为 `恒星邻域 → 太阳系 → 奥尔特云`（种子已改，v18）。**处置：保持用户的后一次决定**；缩放轴（L 值）顺序未动，尺度浏览仍顺畅。此项在自审报告中列为需用户确认。
- **总纲“V1 默认关闭装饰性闪烁”**：项目当前默认是观赏模式并带轻微闪烁，用户已多次确认偏好；沿用现状，科学模式关闭艺术闪烁。
