## 3. 最简化（对照 PRD §0-2、§16.2、§19）

PRD 要求"最简实现、不为凑结构牺牲正确性、不建复杂基础设施"。逐项检查设计新增的机制，**与 PRD 需求或已确认约束无直接对应者一律削减或后置**：

| # | 原设计 | 结论 | 理由 |
|---|---|---|---|
| M1 | `wc_node_closure` 闭包表 | **删除**，改 `wc_nodes.path` 物化路径 | 节点不可移动（已定），路径一次写入不变；子树用范围比较 `path >= p AND path < p_upper`（非 `LIKE`，不受 50 字节限制），祖先在应用层拆分路径。少一张表、少一次批量写、恢复不用重建 |
| M2 | `wc_search` FTS 虚拟表 | **改为基线用 `search_norm` 规范化列 + `LIKE`**；FTS5 trigram 作为 S1 通过后的可选升级 | PRD §12 明确"数据库索引或轻量全文查询即可"。单用户数据量小；省去影子表写入与恢复重建。设阈值：可检索行数超过约 2 万再升级 |
| M3 | `wc_news_sources` | **并入 `wc_node_links`**（`kind='feed'`） | 同为"节点上的外部引用"，字段几乎相同 |
| M4 | `Idempotency-Key` 头 | **删除**；沿用"客户端生成 ULID 作为 `id`"即可去重 | 单用户，重复提交由主键冲突自然处理 |
| M5 | 导出包可选 AES-GCM 口令加密（Q12） | **取消** | PRD 无要求；R2 私有桶＋Access 已保护；增加 CPU 开销（Free 10 ms） |
| M6 | 上传原图在客户端重绘以剥离 EXIF（Q11、S9） | **取消**；仅缩略图由浏览器生成 | PRD 无要求；附件在私有桶。原图保留 EXIF，文档注明 |
| M7 | 写入端点速率限制 `E_RATE_LIMITED` | **删除** | 单用户且在 Access 之后；用 KV 计数会消耗 Free 的 1000 次／天写入额度 |
| M8 | 21 个错误码 | **精简到 13 个** | 关系类、节点占用类各合并为带 `details.reason` 的一个码；UI 只需要区分有不同提示的情形 |
| M9 | 8 个 KV 键（`cfg:version`、`cfg:ui`、`cfg:visual`、`cfg:templates`、`cfg:kinds`、`cfg:news`、`cfg:adapters`、`cfg:sources`） | **合并为 2 个**：`cfg:public:v1`（含 ui／visual／templates／kinds／news 分节与版本号）与 `cfg:adapters:v1`（私有端点） | KV 写额度小；键越少越易维护。`cfg:sources` 运行时无用，删除 |
| M10 | 软删除 `deleted_at` ＋彻底清除流程 | **删除**，只做带确认的硬删除；后悔药用 Time Travel 与导出 | 软删除要求每个查询都带过滤、影响唯一约束与 3 对象计数，PRD 无此需求 |
| M11 | 导出 `ndjson.gz` ＋ 每表 `sha256` ＋ `consistency` 标记 | **改为分页 JSON，仅记行数** | gzip／哈希消耗 CPU；R2 存储量很小；单用户无并发写入。保留 dry-run 与恢复前自动备份（成本低、保护数据） |
| M12 | `wc_attachments.sha256` | **删除**，保留魔数校验 | PRD 无去重需求 |
| M13 | `item_locations.anchor_derived`、`attach_status` 五值 | **删 `anchor_derived`**（有锚点＝人工指定；无锚点由客户端推导并带"位置示意"角标）；**`attach_status` 减为 `exact / fallback / pending`**（节点为空＝未挂靠；回退到根仍算 `fallback`） | 减少可被写错的状态组合 |
| M14 | 触发器 7 个 | **保留 3 个**：3 对象上限（含两端类型）、每节点置顶上限、`wc_item_relations` 的 `from≠to` 与唯一约束靠 CHECK／UNIQUE；其余（`type` 不可变、分类适用类型、一级分类锁定、置顶对象类型）改为服务层校验 | PRD 只强制两项数量约束必须保存端验证；其余服务层即可，减少 S2 风险面 |
| M15 | `geometry_ref`＋R2 `geo-private/`＋`GET /locations/{id}/geometry` | **首版后置**：列保留，端点与前缀等真有大几何时再做（FR-A9 本就是 S 级） | PRD §7.4.7"复杂 GeoJSON 可放静态目录或 R2"为可选 |
| M16 | Spike S8（KV 传播）、S9（EXIF） | **取消**；S7 并入 M5 实现阶段，不单列 | 结论不改变架构 |
| M17 | 提交守卫"三道防线" | **保留，但同一份脚本**供本地钩子与 CI 共用，另开 GitHub push protection（无代码） | 防线的价值高于其成本，PRD §0-12 要求"提交前自查" |
| M18 | 关系类型 `involves / follows / related` | **保留** | `involves` 承担 3 对象上限；`follows`／`related` 对应 PRD §8.4"有方向时保留方向" |
