# F3.8 左侧两个框体固定尺寸与独立隐藏／打开

- 里程碑：M3 ／ 日期：2026-11-11 ／ 提交：未提交（工作区） ／ `git log --grep "F3.8"` 提交后可查
- 对应需求：用户要求“把左侧树形菜单和下方介绍两个框体的长宽高简化固定，加独立的隐藏／打开按钮，现在乱跳”

## 1. 做了什么
- `web/main.js`：**删除 `fitNav()`**（它在树每次展开时把导航面板宽度改到 250px～视口宽，这是“乱跳”的主要原因）；删除“点标题折叠”；新增两个独立开关（导航、介绍）并记住状态（`localStorage` 键 `wc.ui`，读写都有容错；窄屏第一次默认隐藏导航）。
- `web/style.css`：导航＝固定宽 340px × 高 `100vh − 310px`（最小 160px），介绍卡＝固定宽 340px × 高 220px，内容超出框内滚动；去掉宽度过渡与 `max-height` 的重复／覆盖规则；`body.hide-nav / hide-card` 把对应框体滑出并禁用点击；窄屏沿用整宽但高度同样固定（导航 30vh、卡片 15vh）。
- `web/index.html`：顶栏新增两个图标按钮（导航、介绍），隐藏时按钮变淡。

## 2. 关键决定与取舍
- 只有“隐藏／打开”，没有“折叠”这第三种状态，减少状态数。
- 导航固定宽度后，很深的层级名称靠框内横向滚动查看，不再靠加宽面板。

## 3. 验证
- 1400×850 视口：导航 340×540、卡片 340×220；展开树的前几行后两个框体尺寸**完全不变**（实测前后矩形一致）；点两个按钮能分别隐藏／打开，`wc.ui` 已记录状态。
- **未验证**：真实手机竖屏；`prefers-reduced-motion`；窗口很矮（高度 < 500px）时导航最小高度 160px 是否与卡片重叠。

## 4. 合规检查
- 需求遗漏：长、宽、高固定、独立按钮、不再乱跳——均覆盖。
- 需求偏移：未改树内容、卡片内容与交互；本功能不新增视觉债务。
- 最简化设计：删掉一个函数与一个折叠状态，新增两个按钮和一个本地存储键。
