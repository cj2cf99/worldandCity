## 2. 关键决定与取舍

1. **迁移记录表建表语句与 wrangler 默认的 `d1_migrations` 同形，只改名**（设计 §4.5），使 M0 的 S11 验证有可比对象。
2. **迁移整体事务**：每个文件在 `BEGIN…COMMIT` 内执行，失败回滚且不记录；比 D1 的行为更严格不会更宽松，不影响一致性。
3. **文件名强制 `wc_NNNN_描述.sql`**，否则报错，把"与同库其他项目迁移重名"的风险挡在本地。
4. **`wc_nodes` 的 CHECK 只校验自身可判定的部分**：`path` 以 `/id/` 结尾、根节点 `path = /id/`、非根则不是根形态。`path` 是否等于"父.path＋id＋/"依赖父行，按设计 §4.2 由服务层／种子导入校验（F0.2 实现）。
5. `node:sqlite` 的同步接口被包装成 D1 的异步形态，以便后续 Worker 代码在本地与线上共用同一调用方式。

### 4.2 需求偏移

- 未引用其他项目的代码或数据；开发库是本项目新建库（PRD §0-13）。
- 没有触发 PRD §19 "明确不做"的任何项；没有新增依赖、服务或后台。
- 开发库现含结构（迁移产物），不含任何数据行，符合设计 §2.2"只含通用／示例数据"。
- 与设计的一处**细化而非偏离**：设计未规定 `wc_meta.value` 是否可空，实现取 `NOT NULL`（键值对不应有空值）。

### 4.3 最简化设计

- 无第三方依赖；封装仅含后续确定会用的方法（`prepare/bind/all/first/run/batch`，设计 §2.3 明列）。`LocalD1.exec`、`close` 被迁移器与命令行使用。
- 没有做：迁移回滚（down）、迁移校验和、多库管理、连接池——设计与 PRD 均无要求。
- `db.mjs` 导出 `DEV_DB`、`MIGRATIONS_DIR` 目前仅自身使用，F0.2 种子导入将复用；如 F0.2 不用则回收。（跟踪项 → F0.2 检查）

### 4.4 检查中发现并处置

| # | 发现 | 处置 |
|---|---|---|
| 1 | 迁移器初稿读取已执行清单时调用了不存在的方法，属自查发现的实现缺陷（未运行即修正） | 改为通过 `prepare()._runSync()` 读取，删除多余辅助函数 |
| 2 | `wc_nodes` 的 `path` 检查最初用 `LIKE '%/'||id||'/'`：`id` 含 `_`／`%` 时会被当作通配符，校验变宽松 | 改为 `substr` 字面比较；新增回归断言（`a_c` 对 `/abc/` 必须被拒） |
| 3 | `package.json` 的 `engines` 初写 `>=22.5`，而本项目实际依赖的 `node:sqlite` 默认可用的版本需更高 | 取保守值 `>=22.13`；**未在 22.x 上实测**，本机为 Node 26，如需支持 22 须另行验证 |
| 4 | 执行 `migrate` 会修改已入库的二进制开发库（`applied_at` 时间戳） | 属预期；F0.3 守卫的开发库专项检查需覆盖；开发库每次提交只应由迁移／种子产生差异（A-NFR2） |
