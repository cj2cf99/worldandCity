## 1. 做了什么

| 文件 | 职责 |
|---|---|
| [`scripts/guard.mjs`](../../scripts/guard.mjs) | 守卫本体，`--staged`（钩子，读**暂存区内容**）与 `--all`（CI，读已跟踪文件）。规则：路径、内容、种子头、开发库专项 |

三道防线中的第 3 道（GitHub secret scanning／push protection）是平台设置，无代码，**需用户在仓库设置中开启**（见 §5）。

## 2. 规则清单（与设计 §3.2／§3.3 对照）

| 类别 | 规则 |
|---|---|
| 路径 | `.env*`（`.env.example` 除外）、`.dev.vars`；扩展名 `pem key db sqlite sqlite3 bak log` 及 sqlite 的 `-wal/-shm/-journal`；目录 `backup(s) export(s) uploads private secrets node_modules .wrangler`。**唯一例外**：`data/local/worldandcity-dev.sqlite` |
| 内容 | 邮箱、国内手机号形态、私钥块、JWT 形态、`CF_`/`CLOUDFLARE_` 变量赋值、长随机令牌（≥40 位字母数字且大小写数字俱全，排除小写十六进制哈希）；二进制文件（除开发库）一律拒绝 |
| 种子头 | `seed/**`、`config/defaults/**`、`geo/**` 下的 JSON 必须 `_origin ∈ {public, demo}` 且 `_license` 非空 |
| 开发库 | ≤ 5 MB；只许 `wc_` 表；`wc_nodes.origin ∈ {seed, demo}`；`wc_meta`、`wc_d1_migrations` 不限；**其他 `wc_` 表若无专项规则且有数据一律拒绝**（强制以后新增表时补规则） |
| 输出 | 只输出 `路径[:行号] [规则名]`，**不回显命中内容** |

### 4.2 需求偏移

- 守卫**只读不改**文件，不联网，无依赖；符合 PRD §19（无复杂基础设施）。
- 设计 §3.3 把"数据目录白名单"写作白名单；实现为"禁止扩展名＋禁止目录＋开发库例外"（黑名单）。**这是对设计的收窄性偏离**：白名单会在每次新增合法目录时误伤，且当前的"其他路径不得出现数据文件"（§3.2）靠扩展名与二进制拒绝已达成。理由记录在此；若审核认为必须白名单，改为 `--all` 时对非文本文件做允许清单即可。
- 选择把"二进制文件（除开发库）一律拒绝"作为兜底：落实"其他路径不得出现数据文件、图片附件"（§3.2）。M2 需要贴图／模型资源时，须在此规则中为具体目录开例外并在记录中说明许可来源（PRD §22.3）。
- 没有触及任何 PRD §19 项。

### 4.3 最简化设计

- 一个脚本、一个钩子、一个工作流，无新增依赖；钩子与 CI 共用同一入口（复审 M17）。
- 没有做：自动修复、白名单配置文件、规则插件机制、豁免清单（allowlist）。豁免会成为绕过口子，需要时再通过改规则并留记录实现。
- `checkPath／scanText／checkSeedHeader／checkDevDb／checkFiles` 均被测试直接使用，且 `checkFiles` 是 CLI 主路径，没有死代码。

### 4.4 检查中发现并处置

| # | 发现 | 处置 |
|---|---|---|
| 1 | 守卫初稿的"是否主入口"用 URL 字符串比较，在 Windows 路径下不可靠 | 改为与 `db.mjs` 一致的 `resolve(argv[1]) === fileURLToPath(import.meta.url)` |
| 2 | 测试夹具如果直接写违禁字面量，会让仓库自身被守卫拒绝 | 夹具全部在运行时拼接；新增"本仓库已跟踪文件通过守卫"测试作回归 |
| 3 | 钩子脚本若被 `autocrlf` 转成 CRLF，`#!/bin/sh\r` 会在 Git Bash 外失效 | `.gitattributes` 固定 `.githooks/*` 为 `eol=lf`，并设置可执行位（`100755`） |
| 4 | 钩子默认不随克隆生效 | 提供 `npm run hooks:install`；**不是自动生效**，CI 作为兜底；README 补充说明（见下） |
| 5 | 开发库中若将来有新 `wc_` 表被写入数据而忘记补守卫规则，会静默放行 | 采用"无规则即有数据即拒绝"的失败即关闭策略并有测试 |
| 6 | 国内手机号规则对 13 位以上的长数字（如时间戳）可能误报 | 使用前后非数字断言；已有"长数字不误报"测试 |
| 7 | **守卫在 F0.3 自身的首次真实提交中拦截了测试文件**：端到端夹具里 `git config user.email` 写了字面邮箱（命中 `email` 规则，`tests/guard.test.mjs:92`）。说明规则在真实提交路径上有效，也说明我对 #2 的"夹具运行时拼接"执行得不彻底。当时的回归测试和 `--all` 都只扫**已跟踪**文件，而 `guard.test.mjs` 本身尚未被跟踪，所以没有扫到它；真正扫到它的是 `--staged`。这也是"提交前必须走钩子"的价值所在 | 该处改为运行时拼接；重新跑全部测试与守卫后再提交。提交未使用任何绕过手段（未用 `--no-verify`） |
