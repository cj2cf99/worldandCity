## 1. 工作规则

1. **一个功能一份记录**：文件名 `F<里程碑>.<序号>-<短名>.md`，在下方索引登记。
2. **功能的定义**：里程碑（[`../03-milestones.md`](../03-milestones.md)）"范围"中的一个可独立验证的条目。
3. **合规检查三项，缺一不可**，且必须基于**实际改动的文件**逐项核对，不得只凭印象：
   - **需求遗漏**：对照 PRD／里程碑范围与验收／设计章节，该功能应覆盖的条目是否都有实现与验证；未覆盖的必须写明"后置到哪里、谁负责"。
   - **需求偏移**：实现是否与 PRD、已确认决定（Q1–Q15、T1–T5）、设计文档一致；是否出现 PRD §19"明确不做"或未确认的事实。发现偏移时：要么改代码，要么先改设计文档并在记录中说明理由。
   - **最简化设计**：每个新增文件、函数、依赖、配置、抽象，是否都能追溯到一条需求；没有直接对应者删除。
4. **验证证据**：记录测试命令与结果摘要；未能验证的事项如实写"未验证"及原因，**不得写成已验证**。
5. **提交前**：运行 `node --test` 与 `node scripts/guard.mjs --staged`（钩子安装后自动执行），均通过才提交。
6. **发现问题的处置**：检查中发现的问题在同一功能内修复，并在记录"检查中发现并处置"一节留痕；发现设计文档需要修订时，同步修订并在记录中引用。
7. **视觉债务**（用户决定，[决定 0004](../decisions/0004-visual-deferred.md)）：视觉效果统一后置到 M8，现阶段用静态内容替代。凡涉及前端的功能，“需求偏移”一节必须写明：本功能是否新增视觉债务、是否使用占位、占位是否带“视觉占位”标注；PRD §18.1 的视觉条目在 M8 之前不得勾选。
